# 模式G：报告增量更新（--update）

> 本文件由 SKILL.md 路由加载。执行前确保已理解核心原则。

## --update 报告增量更新模式

当用户通过 `--update` 触发时，你的任务是：**找出已有背调报告，只搜索报告日期之后的新变化，以增量章节追加到原报告末尾**。

### 阶段 0：定位已有报告

1. 如果用户指定了公司名（`--update "公司名"`）→ 用 `ls ~/Desktop/{公司名}_求职背调_*.md` 找最近的报告文件
2. 如果用户没指定公司名（`/qiuzhi --update`）→ 用 `ls ~/Desktop/*_求职背调_*.md` 列出所有报告，让用户选择要更新哪一个
3. 如果找不到任何报告 → 提示"没有找到该公司的背调报告，建议先跑一次 /qiuzhi --deep {公司名}"

从文件名提取原报告日期（如 `帆软_求职背调_深度_20260516.md` → 2026-05-16）。

### 阶段 1：增量搜索（4 个并行搜索）

只搜近期变化，搜索词聚焦"新"和"变化"：

```
搜索 1: "{公司名} 最新动态 新闻 融资 产品 {今年}"
搜索 2: "{公司名} 裁员 组织调整 高管变动 劳动仲裁 风险 {今年}"
搜索 3: "{公司名} 新产品 新功能 战略变化 {今年}"
搜索 4: "{公司名} 招聘规模 薪资变化 福利 社保 公积金 调整 {今年}"
```

### 阶段 2：追加更新章节

用 Read 读取原报告末尾，用 Write 或 Edit 在原报告末尾追加以下格式的更新章节：

```markdown
---

## 🔄 近期更新（{当前日期} 刷新）

> 原报告日期：{日期} | 距上次报告 {天数} 天
> 本次更新基于近期公开信息，重点关注对求职决策有实质影响的变化

### 📰 重大新闻

| 日期 | 事件 | 求职影响 | 来源 |
|------|------|---------|------|
| | | | |

### 📊 关键指标变化

| 指标 | 原报告状态 | 当前状态 | 变化方向 |
|------|----------|---------|---------|
| 融资/资金 | | | 🟢 / 🟡 / 🔴 |
| 招聘规模 | | | |
| 业务方向 | | | |
| 风险信号 | | | |

### 🎯 对求职决策的影响

- **原综合评分**：{从原报告提取} → **调整建议**：{是否变化及理由}
- **新风险**：{原报告未覆盖的新风险}
- **新机会**：{比如新业务线=新岗位、新产品=新技术栈需求}

### ⚡ 建议行动

- {1-2 条基于变化的具体行动建议}

> 📄 更新由 /qiuzhi --update 生成 | 信息来源：公开网络搜索
```

> 如果搜不到近期任何显著变化，诚实说明"近 {天数} 天内未发现对求职有实质影响的变化"，不编造更新内容。

## 实现注意事项（本模式专属）

### 报告增量更新模式专属

1. **定位已有报告**：用 `ls ~/Desktop/` 查找匹配的背调报告文件，从文件名提取日期。找不到时提示先跑一次背调
2. **追加不覆盖**：更新内容追加到原报告末尾，不修改原报告已有内容
3. **搜不到就诚实说**：如果近期没有显著变化，如实说明，不编造更新内容
